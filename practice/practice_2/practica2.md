# Практические задания по теме «Системы ввода-вывода и интерфейсы» - решения

## Задача 1. Терминология и определения

**Ответ:** 1-Г, 2-В, 3-Б, 4-А, 5-Е, 6-Д.

Пояснение (по слайдам 8-9):
- **Система ввода-вывода (СВВ)** - средства взаимосвязи и передачи информации, объединяющие ЦПр, ОЗУ и ПУ (Г).
- **Интерфейс** - средства и правила, обеспечивающие взаимосвязь устройств между собой (В).
- **Магистраль** - совокупность всех линий интерфейса (Б).
- **Шина** - группа линий интерфейса, соответствующая определённому функциональному назначению (А).
- **Канал** - среда передачи информации в виде определённых сигналов (Е).
- **Линия интерфейса** - электрический проводник, по которому распространяется сигнал (Д).

## Задача 2. Классификация интерфейсов

| Признак классификации | Варианты |

| По способу передачи данных | 1. Параллельный; 4. Последовательный |
| По организации обмена | 2. Симплексный; 5. Полудуплексный; 7. Дуплексный |
| По способу синхронизации | 3. Синхронный; 6. Асинхронный |
| По архитектуре (параллельный интерфейс) | 8. Трёхшинный; 9. Двухшинный |

Пояснение (слайды 12-14): параллельный - одновременная передача всех или части разрядов; последовательный - побитовая передача по одной линии. Симплексный - в одну
сторону, полудуплексный - в две стороны по одним линиям в разные моменты, дуплексный - одновременно в обе стороны. Синхронный - переключение по фронту
синхроимпульсов, асинхронный - внутри такта. Трёхшинный - шины данных, адреса, управления; двухшинный - совмещённая шина адреса/данных плюс шина управления.

## Задача 3. Расчёт скорости передачи

**а) Параллельный интерфейс:** f = 100 МГц, N = 16 бит.
- V = f * N = 100*10^6 * 16 = **1,6*10^9 бит/с = 1,6 Гбит/с**
- В байтах: 16 бит = 2 байта, V = 100*10^6 * 2 = **2*10^8 байт/с = 200 Мбайт/с**

**б) Последовательный интерфейс:** f = 2,5 ГГц, 1 бит за такт.
- V = f = **2,5*10^9 бит/с = 2,5 Гбит/с**
- В байтах: V = 2,5*10^9 / 8 = **312,5*10^6 байт/с = 312,5 Мбайт/с**

**в) Сравнение и вывод.**
- Параллельный: 1,6 Гбит/с (200 Мбайт/с) при f = 100 МГц.
- Последовательный: 2,5 Гбит/с (312,5 Мбайт/с) при f = 2,5 ГГц.
- Последовательный интерфейс при более высокой тактовой частоте обгоняет параллельный, хотя за такт передаёт один бит.

Почему последовательные интерфейсы всё шире используются (слайд 15):
1. **Простота и дешевизна**: для данных нужна всего одна линия (пара проводников при дифференциальной передаче), меньше контактов разъёма, ниже стоимость кабеля и
монтажа.
2. **Высокая тактовая частота**: последовательные интерфейсы работают на f > 2 ГГц, что компенсирует побитовую передачу.
3. **Отсутствие проблемы перекоса синхронизации**: в параллельном интерфейсе с ростом частоты разряды приходят неодновременно, и это ограничивает fпар < 150 МГц; в
последовательном такой проблемы нет.
4. **Помехоустойчивость**: дифференциальная передача по витой паре эффективно подавляет синфазные помехи.
5. **Масштабируемость**: для повышения производительности используют параллельную передачу группы разрядов слова по нескольким последовательным каналам (multilane),
сохраняя простоту каждого канала.

## Задача 4. Задатчик и исполнитель (рис. 1.3)

1. **В системе «процессор - ОЗУ»** процессор (ЦПр) **всегда задатчик (Master)**, а ОЗУ **всегда исполнитель (Target)**. Процессор начинает и управляет обменом, ОЗУ
принимает или выдаёт данные по его команде.

2. **Да, ПУ может быть и задатчиком, и исполнителем.** Пример: контроллер прямого доступа к памяти (ПДП/DMA) или сетевой адаптер - ПУ, которое само инициирует
передачу данных в ОЗУ (задатчик), а в операции вывода на принтер ПУ выступает исполнителем, принимая данные от процессора. То есть ПУ - «и то и другое» (слайд 16).

3. **Запись** - передача информации **от задатчика к исполнителю** (например, ЦПр -> ПУ/ОЗУ). **Чтение** - обратное направление, **от исполнителя к задатчику** (ПУ
ОЗУ -> ЦПр). Источник - устройство, выдающее информацию, приёмник - принимающее.

4. **Зачем распределять функции управления** (слайд 16): для **минимизации загрузки процессора** при выполнении ввода-вывода. Процессор выдаёт лишь команду, а
рутинные операции (адресация, пересылка, контроль состояния, прерывания) выполняют главный контроллер (канал) ввода-вывода, контроллер ПУ и блок управления ПУ. Это
позволяет процессору параллельно решать другие задачи и повышает общую производительность системы.

## Задача 5. Анализ структуры системы ввода-вывода (рис. 1.8)

1. **Основные компоненты:**
- **Структура «а»** (с раздельными интерфейсами): процессоры (Пр), ОЗУ, интерфейсный блок, интерфейс ОЗУ, каналы ввода-вывода, контроллеры ввода-вывода, ПУ
интерфейс ПУ, интерфейс ввода-вывода.
- **Структура «б»** (с единым системным интерфейсом): процессор (Пр), ОЗУ, системный интерфейс (общая шина), системный контроллер, контроллер прерывания,
контроллер ПДП, контроллеры ввода-вывода, ПУ.

2. **Принципиальное отличие:** в структуре «а» используются **раздельные интерфейсы** - интерфейс ОЗУ, интерфейс процессора, интерфейс ввода-вывода, интерфейс ПУ;
обмен идёт через каналы ввода-вывода. В структуре «б» всё объединено **единым системным интерфейсом (общей шиной)**, к которому через системный контроллер подключены
процессор, ОЗУ и контроллеры (прерывания, ПДП, ввода-вывода). Структура «б» проще и универсальнее, но общая шина является разделяемым ресурсом.

3. **Для современных ПК характерна структура «б»** - с системной шиной (магистральный интерфейс). Обоснование: унификация и стандартизация интерфейса, простота
наращивания (подключение новых контроллеров к общей шине), меньшая стоимость и конструктивная простота. Современные реализации - шины PCI Express, ранее FSB/BSB, - по
сути развитие магистрального принципа; функции «а»-структуры (каналы) частично сохраняются в виде контроллеров-концентраторов (чипсет, хаб).

4. **Роль в структуре «б»:**
- **Системный контроллер** - связывает процессор и ОЗУ с системной шиной, управляет доступом к памяти и арбитражем шины (кто в данный момент задатчик),
обеспечивает обмен между процессором, памятью и периферией.
- **Контроллер прерывания** - принимает запросы прерывания от ПУ и контроллеров, приоритезирует их и формирует сигнал прерывания процессору, чтобы тот переключился
на обслуживание устройства (реализует механизм прерываний, показанный на рис. 1.4 - «вектор прерывания»).
